# 歌单订阅（MoviePilot V3）

把网易云 / QQ音乐 / 酷狗 / 酷我 / 咪咕 / Spotify 等平台的歌单同步成 Plex / Emby 的播放列表，并把媒体库里搜不到的曲目汇总成一份**待订阅清单**，由你在数据页勾选后一键推送订阅，成功的留进**订阅历史**（带歌曲 / 专辑 / 歌手的**来源链接**，即该曲目在最初所属平台上的详情页）。

**核心能力：**

1. **同步 / 创建歌单** —— 网易云、QQ音乐、酷狗、酷我、咪咕、Spotify 的歌单，以及网易云每日推荐（歌单 / 歌曲），同步成 Plex / Emby 的音乐播放列表，曲库里已有的曲目不重复添加；
2. **库内缺失歌曲订阅** —— 同步时媒体库里搜不到的曲目，按「歌手 + 歌名」跨歌单去重后落到清单里（含歌曲名、时长、歌手、专辑名称、来源歌单、命中次数），在数据页逐行勾选「歌曲」或「专辑」，点「订阅」推送给 MoviePilot 的音乐订阅；
3. **跨平台搜索与下载**（可开关）—— 在「搜索页」按关键词跨多个平台搜歌，结果带「来源链接」；**网易云支持真实下载**（经 ncm-api 取音频直链落盘），其余平台无直链时可回退到你自建的 **bitmagnet** 检索种子并推送到下载器；**付费 / 会员内容一律不绕过**（详见第 8 节）；
4. **智能歌单生成** —— 给一个种子（一首歌 / 一位歌手 / 一个关键词），插件按特征相似度 + 多样性约束生成一份风格连贯的歌单（详见第 9 节）。

插件**不会**在同步过程中自动订阅任何东西，每首歌怎么订阅都由你决定。

## 1. 部署 ncm-api（网易云取数的前置条件）

网易云的登录与取数全部交给本地部署的 [ncm-api](https://github.com/moefurina/ncm-api) 容器，插件不内置加密实现。  
ncm-api 容器端口 3000 与 MoviePilot 冲突，宿主机映射端口统一用 **1630**。

**与 MoviePilot 同一个 docker-compose（推荐）**

```yaml
services:
  moviepilot:
    image: jxxghp/moviepilot:latest
    # ……省略自身配置……
  ncm-api:
    image: moefurina/ncm-api:latest
    container_name: ncm-api
    restart: always
    ports:
      - "1630:3000"
```

服务地址填 `http://192.168.X.X:1630`（同一 compose 网络内可写 `http://ncm-api:3000`）。

**ncm-api 跑在宿主机**

```bash
docker run -d --name ncm-api -p 1630:3000 moefurina/ncm-api:latest
```

服务地址填 `http://127.0.0.1:1630`（MoviePilot 也跑在宿主机时）或宿主机内网 IP。

**在局域网另一台机器**：服务地址填 `http://那台机器的内网IP:1630`，注意那台机器要能访问网易云。

### 2.1 网易云登录

只保留**扫码登录**一种方式。退出登录是一次性按钮动作，插件不再有「Cookie 保活」这类后台开关：

点「获取二维码」→ 用网易云音乐 App 扫码 → 页面自动轮询到授权成功。登录凭证与歌单取数全部由 ncm-api 持有，插件不保存密码，也不再提供短信验证码、账号密码、手动粘贴 Cookie 的入口。

### 2.2 订阅人

订阅时写进宿主订阅记录的「用户」栏位，默认 **`歌单订阅`**。想按人区分订阅来源（或跟手工订阅区分开）就改这里。

搜索来源**不在插件里选**：插件不指定任何音乐来源，搜哪些库完全由宿主自己的音乐元数据源设置决定。要调整命中率，请去「设置 → 音乐元数据源」改宿主的来源配置。

### 2.3 歌单配置格式

每行一条，空行与 `#` 开头的注释行会被忽略：

```
# 网易云 / QQ音乐：歌单ID:播放列表名称[:emby用户名]
2388086885:我喜欢的音乐
https://music.163.com/playlist?id=2388086885:午后咖啡
2388086885:收藏:张三,李四

# 其它平台（酷狗 / 酷我 / 咪咕 / Spotify）：平台|标识符|播放列表名称[:emby用户名]
spotify|https://open.spotify.com/playlist/xxx:每日推荐
kugou|12345:华语精选
```

- `播放列表名称` 是同步后在 Plex / Emby 里显示的歌单名，必填；
- `emby用户名` 只对 Emby 有效（多人各用各的播放列表），多个用户用半角逗号分隔；
- 网易云 / QQ音乐的歌单可以直接粘贴歌单链接，插件会自己从中取出数字 ID；
- 酷狗 / 酷我 / 咪咕 / Spotify 写在「其它平台歌单」栏位，用 `|` 分隔（标识符可能是 URL，
  冒号会和 `https://` 冲突）。

### 2.4 曲目精确匹配

- **开启**（默认）：按「歌名 + 歌手」精确判断曲库里是否已有这首；
- **关闭**：只按歌名模糊匹配，匹配更宽松，但可能并入同名不同版本的曲目。

### 2.5 外部接口限速

公开接口都有频率限制，插件在请求侧自己排队，宁可多等几秒也不要整轮失败：

| 数据源               | 限速            | 说明                              |
| ----------------- | ------------- | ------------------------------- |
| QQ音乐              | **1 次 / 5 秒** | 模块级共享节流，跨歌单生效；等待时日志会写明「已等待 N 秒」 |
| bitmagnet（自建实例）   | 1 次 / 1 秒     | 自己的实例也要客气一点                     |
| 网易云（自部署 ncm-api）  | 不限            | 本地服务，自己控制即可                     |

所以配了 N 个 QQ音乐歌单时，一轮同步至少多花 `(N - 1) × 5` 秒，属正常现象。

### 2.7 bitmagnet（自建 BT 索引器）

bitmagnet 是自建的 BitTorrent 索引器 / DHT 爬虫，自带 GraphQL 接口（默认
`http://<host>:3333/graphql`）。当某个平台**给不出可播放的音频直链**时
（未开放接口、曲目无该音质档位等），插件可以退一步：拿「歌手 + 歌名」去你自己的
bitmagnet 实例里检索种子，再把磁力链接推给宿主已配置的 qBittorrent / transmission。

**为什么用自己部署的实例：**

- 索引结果来自你自己的实例，**不依赖任何外部站点**，也不存在被公共索引站封禁的问题；
- 检索走 GraphQL，插件内置多份候选查询（v0.10+ 的 `torrentContent { search }` 与更早版本的
  顶层 `search`），首次调用时依次探测、命中后缓存，**不怕版本差异**；
- 默认不鉴权；若实例前面挂了反向代理需要 token，填「API Key」即可（以 `X-API-Key` 头发送）。

**匹配方式**：拿到结果后按「歌名命中 +0.6 / 歌名分词全命中 +0.35 / 歌手命中 +0.3 /
目标格式（如 flac）出现在命名里 +0.2 / 有做种 +0.1」打分，取最高分那条；
完全不相干的结果记 0 分，**宁可返回「没找到」也不硬凑**。

> **边界不变**：插件依旧不解密任何平台音频、不绕过付费 / DRM。bitmagnet 只是换了一个
> 公开可得的获取渠道，检索到什么取决于你自己实例索引到的资源。请确保你对下载内容
> 拥有合法权利，本插件不对结果做任何版权判断。

## 3. 数据页（库内缺失曲目）

列表与你看到的截图完全一致：

| 序号 | 选择歌曲 | 选择专辑 | 歌曲名称 | 时长    | 歌手 | 专辑名称  |
| -- | ---- | ---- | ---- | ----- | -- | ----- |
| 1  | ○    | ●    | 我记得  | 05:29 | 赵雷 | 署前街少年 |
| 2  | ●    | ○    | 红豆   | 04:16 | 王菲 | 畅游    |

- **同一序号的「歌曲」与「专辑」二选一**：同一个 `seq` 只能是一种粒度，点另一个会自动切过来；
- **全选**：把当前筛选出来的记录全部选中为「歌曲」；
- **反选**：未勾选 → 勾选歌曲；已选歌曲 → 切成专辑（没有专辑信息则取消）；已选专辑 → 取消；
- **订阅**：按勾选的粒度逐条推送给 MoviePilot 音乐订阅；**成功的记录从清单移出并留一份订阅历史**，只有失败的会留在清单里，行内标红并写明失败原因；
- **来源链接**：每行直接给出这首歌在**来源平台**（网易云 / QQ音乐 / 酷狗 / 酷我 / 咪咕 / Spotify）上的**歌曲 / 专辑 / 歌手**详情页链接，随同步算好、无需再点「查询链接」，点开即回到那家平台上的具体歌曲（查不到对应 ID 的维度置灰）；
- **移除 / 清理**：移除勾选的记录，或清理「订阅失败」的记录 /「全部」；
- 顶部统计卡显示**总数**、**订阅失败数**与**订阅历史**条数，另有关键词搜索、数据源过滤与分页（每页 20 / 50 / 100 条）。

### 3.1 订阅历史

顶部「待订阅清单 / 订阅历史」两个视图随时切换。订阅成功的条目会留档在这里：

| 序号 | 歌曲名称 | 歌手     | 专辑名称 | 时长    | 粒度 | 订阅人  | 订阅时间                | 来源链接         |
| -- | ---- | ------ | ---- | ----- | -- | ---- | ------------------- | ------------ |
| 1  | 起风了  | 买辣椒也用券 | 起风了  | 05:26 | 歌曲 | 歌单订阅 | 2026-09-23 15:04:11 | 歌曲 / 专辑 / 歌手 |

- 历史里直接给出歌曲、专辑、歌手三个来源链接（指向最初所属平台，取不到的置灰）；
- 订阅 ID 一并记录，方便回宿主的订阅列表里对照；
- 支持按关键词搜索、按订阅粒度（歌曲 / 专辑）过滤，可单独清空；**清空历史只动插件自己的留档，不会删除宿主里的订阅**。

清单上限 1000 条，超出后丢弃最早的记录。

**执行顺序**：一次同步里先把所有歌单推完（该加的歌照常加进播放列表），每个歌单里搜不到的歌只做登记并按「歌名 + 歌手」跨歌单去重（命中次数累加、来源保留第一次见到的歌单），全部推完后统一写入清单。中途出错也不丢已发现的缺歌。

## 4. 订阅是怎么落的

全链路走宿主的**官方音乐接口**，插件自己不实现任何来源协议（豆瓣也是宿主内置的链路）：

1. **搜索** —— 拿「歌手 + 歌名」调宿主的音乐搜索（`GET /api/v1/music/search`），按实体类型过滤出单曲 / 专辑候选。**不指定来源**，由宿主按自己的音乐元数据源设置决定搜哪些库；
2. **识别** —— 对命中的候选按「来源 + 媒体 ID」调官方识别（`POST /api/v1/music/recognize`）拿到完整详情。走的是**音乐专用入口**（不经过会把请求广播给影视插件的通用识别链）；歌名对不上或歌手明显不符的候选直接放弃，专辑拿不到曲目总数的按失败处理；
3. **订阅** —— 识别结果带 `media_source` / `media_id` 交给 `SubscribeChain` 显式订阅，并带上配置里的**订阅人**。

选「歌曲」按单曲（`recording`）订阅，选「专辑」按所在专辑（`album`）订阅。只采信**音乐来源**的识别结果：宿主识别是插件优先的模块广播，影视类插件若不校验 `media_source` 就按标题返回结果会抢先命中，这类结果一律按未识别处理。

搜不到、识别不出身份、或候选对不上的曲目，会留在清单里并写明原因（例如「未搜索到匹配的曲目」「识别结果不是音乐来源」），等你自己决定要不要换个关键词或换来源再试。

## 5. 定时任务

在「运行设置」填五位 cron 表达式即可，例如每天凌晨 4 点：`0 4 * * *`。  
留空表示不定时运行，只能手动点配置页底部的「立即运行一次」。保存配置不会触发同步——保存入口在宿主头部右上角，与运行动作互不打扰。

## 6. 接口

完整路径为 `/api/v1/plugin/MusicSubscribe/<path>`：

| 方法   | 路径                   | 说明                                                                                                          |
| ---- | -------------------- | ----------------------------------------------------------------------------------------------------------- |
| GET  | `/status`            | 版本、开关、登录态、媒体服务器、清单概览、上次同步统计                                                                                 |
| GET  | `/probe`             | 探测 ncm-api 连通性                                                                                              |
| POST | `/qrcode`            | 获取扫码登录二维码                                                                                                   |
| GET  | `/qrcode/status`     | 查询扫码状态（成功后自动保存登录）                                                                                           |
| POST | `/logout`            | 退出网易云登录并清除本地凭证                                                                                              |
| POST | `/run`               | 立即运行一次同步                                                                                                    |
| GET  | `/pending`           | 查询库内缺失曲目清单（`scope=all/failed`，`failed` 为订阅失败的记录）                                                            |
| POST | `/pending/subscribe` | 按勾选的粒度推送订阅（body：`{"items":[{"seq":1,"target":"song"}]}`），成功的记录从清单移出并写入订阅历史                                  |
| POST | `/pending/remove`    | 从清单移除勾选的记录                                                                                                  |
| POST | `/pending/clear`     | 清理清单（`scope=all/failed`）                                                                                    |
| POST | `/pending/link`      | 查询单条曲目的来源链接（body：`{"seq":1}`，返回歌曲 / 专辑 / 歌手三个链接，指向该曲最初所属平台）                                       |
| GET  | `/history`           | 查询订阅历史（只含订阅成功的条目，支持 `keyword` 搜索）                                                                           |
| POST | `/history/clear`     | 清空订阅历史（不影响宿主订阅列表）                                                                                           |
| GET  | `/platforms`         | 列出全部平台及其可用性（含停服说明），供前端展示与搜索默认平台                                                                             |
| GET  | `/search`            | 跨平台关键词搜索（`keyword`、`platforms`、`limit`），返回去重后的曲目行（含来源链接）                                                    |
| POST | `/download`          | 下载一条曲目（body：`{"platform":...,"source_id":...,"title":...}`）；网易云返回 `kind:"direct"` 落盘，无直链且开了 bitmagnet 时返回 `kind:"torrent"`（详见第 8 节） |
| POST | `/bitmagnet/test`    | 探测 bitmagnet 连通性并回读版本号（body 可选 `{"url","api_key"}`，用于保存前试连）                                          |
| GET  | `/smartlist`         | 智能歌单生成（`seed` 标题/歌手/专辑 + `keyword` 扩展 + `size`），返回按相似度排序的曲目行                                                |

## 7. 前端开发

```bash
cd frontend
npm install
npm run build    # 产出 frontend/dist/assets/remoteEntry.js（宿主按联邦方式加载 ./Config、./Page 与 ./Search）
npm run dev      # 本地预览 http://localhost:5101（自带 mock 接口，含 /platforms、/search、/smartlist、/download、/bitmagnet/test）
```

## 8. 跨平台搜索与下载

### 8.1 搜索页

配置页打开「启用搜索」后，插件主界面出现「搜索页」标签页，提供两个子功能：

- **跨平台搜索**：输入关键词，默认在「网易云 / QQ音乐 / Spotify / 酷狗 / 酷我 / 咪咕」中检索（结果区可勾选要搜的平台），结果按「平台 + 曲目 ID」去重，每行带该曲目在所属平台上的**来源链接**；
- **智能歌单**：见第 9 节。

### 8.2 真实下载能力与边界

下载从配置到接口到界面已完整打通：**网易云支持真实下载**，其余平台暂不支持直链。

**网易云**：插件经你自部署的 **ncm-api** 调 `/song/url` 取音频直链，再按  
`{歌手}/{专辑}/{歌名}.{格式}` 落盘到「下载路径」。音质档位跟随「下载格式」配置  
（`flac`→`lossless`、`mp3`→`exhigh`、`m4a`/`ogg`→`standard`、`wav`→`hires`）。  
**不会做的事（明确边界）**：

- 不解密音频、**不绕过付费 / 会员限制、不规避 DRM** —— 平台不给地址就是给不了，    
  把原因如实告诉你；
- 平台只返回**试听片段**时按「不支持」处理，不拿片段冒充完整音频；
- 因此**付费 / 会员专属内容下不了**，请通过平台官方渠道（购买 / 会员 /    
  官方客户端离线下载）获取。

适配器返回的描述符决定走哪条路：

| 描述符 `kind` | 含义                    | 来源 / 路由                                          |
| ---------- | --------------------- | ------------------------------------------------- |
| `direct`   | 平台返回了可播放的音频地址         | 网易云（经 ncm-api）；按「下载路径 / 格式」落盘到 `{歌手}/{专辑}/{标题}.{格式}` |
| `torrent`  | 返回 magnet，推送给下载器      | bitmagnet 检索命中；按「下载器」配置推到 qBittorrent 或 transmission（auto 时自动探测） |
| `none`     | 平台未开放直链 / 该内容为付费或试听片段，且 bitmagnet 也未命中 | 只在前端提示原因，不发请求                                     |

> 「下载」按钮始终可见，点了之后会明确告诉你：下成了（含落盘路径或种子名），还是为什么下不了。

**决策顺序**：

```
平台有直链？ ──是──▶ direct 落盘
     │否
     ▼
bitmagnet 已开启且已配置？ ──是──▶ 用「歌手 + 歌名」检索 → 命中则 torrent 推送到下载器
     │否                          └─ 未命中则 none（附平台原始原因 + 未命中）
     ▼
none：把平台原因如实回给用户
```

走 bitmagnet 回退时，返回结果里带 `source: "bitmagnet"` 与种子名 / 大小 / 做种数，
前端消息会写明「平台未提供直链；已改用 bitmagnet 检索到种子…」。

## 9. 智能歌单生成

音乐订阅常用于「听到一首好歌，想顺手收一批同风格」的场景。智能歌单不依赖任何外部推荐 API，纯靠本地已采集曲目的**特征相似度 + 多样性约束**生成，离线也能跑：

1. **特征抽取**：把每首歌的「歌手 + 专辑 + 歌名」拆成小写字母数字 token 集合，作为轻量向量；
2. **相似度打分**（0~1）：同歌手 +0.45（最强信号）、同专辑 +0.25、标题 / 专辑 token 的 Jaccard 重合加权 0.40、歌名几乎一致 +0.15；
3. **多样性约束**：同一歌手最多保留 N 首（默认 3），避免歌单被单个歌手占满；
4. **去重 + 排序**：按 `(平台, 曲目ID)` 去重，按相似度降序输出。

使用：在「搜索页 → 智能歌单」填种子（标题 / 歌手 / 专辑，至少其一）与「扩展关键词」（可选，用于从更多平台补充候选），设定目标条数，点「生成」即可得到带相似度进度条与来源链接的歌单；每行可单独「下载」。
