# 歌单订阅（MoviePilot V3 插件）

把**网易云 / QQ 音乐 / 汽水音乐**的歌单，以及**场景化「听歌模式」**，自动同步成
**Plex / Emby** 播放列表；媒体库里没有的歌曲会先进入**本地待处理清单**，去网易云
校验确认真身与专辑后，再**手动推送**成 MoviePilot 音乐订阅。设计目标是
**尽量减少人工维护**：选好场景、贴一次链接之后，每天定时自动同步，内容跟随官方更新。

---

## 功能总览

| 功能 | 说明 |
| --- | --- |
| 歌单同步 | QQ音乐 / 网易云 / 汽水音乐三处**独立**配置，同步到 Plex 或 Emby（多用户） |
| 听歌模式 | 内置「早晨音乐 / 纯音乐精选 / 学习专注 / 运动节奏 / 睡前放松 / 通勤路上」场景预设，可多选；每天自动取网易云该分类热门歌单同步，零人工维护 |
| 缺歌处理 | 库里搜不到的歌曲默认**缓存到待处理清单**，可一键去网易云校验并手动推送订阅；也可改成立即自动订阅或不处理 |
| 音乐订阅 | 推送时按「仅单曲 / 单曲优先失败转所在专辑 / 仅专辑」转订阅，豆瓣音乐源优先识别，MusicBrainz 兜底 |
| 每日推荐 | 网易云每日推荐歌单与歌曲同步，失败原因可读、可一键诊断 |
| Cookie 保活 | 每天检查登录状态，密码方式失效自动重登 |
| 详情页 | 统计卡片 + 同步明细卡片网格 + 订阅明细 + 待处理清单 |
| 订阅管理 | 按 ID 删除 / 清理本插件订阅 / 清理身份不完整订阅 |

---

## 1. 部署 ncm-api（网易云取数前置条件）

网易云登录与取数全部经本地部署的 [moefurina/ncm-api](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced) 转发。
ncm-api 默认容器端口 3000 与 MoviePilot 冲突，宿主机映射端口统一用 **1630**。

### 方式一：与 MoviePilot 同一个 docker-compose（推荐）

```yaml
services:
  moviepilot:
    image: jxxghp/moviepilot:latest
    # ……省略自身配置……
  ncm-api:
    image: moefurina/ncm-api:latest
    container_name: ncm-api
    restart: always
    ports:
      - "1630:3000"
```

插件里的服务地址填：`http://192.168.X.X:1630`
（同一 compose 网络内可写 `http://ncm-api:3000`，跨机写宿主机映射地址）。

### 方式二：ncm-api 跑在宿主机

```bash
docker run -d --name ncm-api -p 1630:3000 moefurina/ncm-api:latest
```

插件服务地址填 `http://127.0.0.1:1630`（MoviePilot 也跑在宿主机时）或宿主机内网 IP。

### 方式三：ncm-api 在局域网另一台机器

插件服务地址填 `http://那台机器的内网IP:1630`，注意那台机器要能访问网易云。

## 2. 配置项

### 2.1 基础

| 配置 | 说明 |
| --- | --- |
| ncm-api 服务地址 | 如 `http://192.168.1.100:1630`，保存后自动探测连通性 |
| 网易云登录方式 | 扫码 / 短信验证码 / 密码 / Cookie，四选一，按选择联动显示对应栏位 |
| Cookie 保活 | 每天检查登录状态并尝试刷新；密码方式失效时自动重登 |
| 媒体服务器 | 从宿主配置里读取 Plex / Emby，可多选 |
| 定时 / 立即运行一次 | 每天定时同步；保存后也可手动触发 |

### 2.2 听歌模式（零人工维护的场景化歌单）

**这是「早晨音乐」「纯音乐精选」这类需求的推荐用法**：勾选预设即可，不需要找歌单 ID。

| 预设 | 网易云分类 |
| --- | --- |
| 早晨音乐 | 清晨 |
| 纯音乐精选 | 轻音乐 |
| 学习专注 | 学习 |
| 运动节奏 | 运动 |
| 睡前放松 | 夜晚 |
| 通勤路上 | 通勤 |

- 每个预设每天自动取**该分类的热门榜首歌单**，同步成与场景同名的媒体库播放列表；
  网易云官方与达人会持续更新这些场景歌单，插件内容自动跟随。
- **自定义场景**：一行一个，格式 `网易云分类:播放列表名`（省略名称时直接用分类名），例如：

  ```
  车载:通勤路上
  古风
  ```

> **为什么用网易云实现而不是汽水？** 汽水音乐的场景电台（早晨音乐、纯音乐精选等）
> 没有公开接口，公共解析服务也只支持 `playlist` / `user` 两种类型，无法程序化取数；
> 而网易云的官方场景歌单覆盖同样需求且每日更新，插件已接入 ncm-api，
> 因此听歌模式用网易云场景分类实现。汽水歌单本身仍可用分享链接同步（见 2.5）。

### 2.3 缺歌处理方式与订阅粒度

**处理方式**（配置页「库内缺失曲目的处理方式」）：

| 选项 | 行为 |
| --- | --- |
| **缓存待处理（默认，推荐）** | 只把歌名、歌手、专辑、来源、命中次数写进本地待处理清单，**不产生订阅**；你在配置页校验、确认后再手动推送 |
| 立即自动转为音乐订阅 | 同步时就按下面的粒度直接订阅，全程无人值守（老行为） |
| 不处理 | 只在日志与详情页记录，不留清单也不订阅 |

选「缓存待处理」的原因是：库里搜不到的歌往往在 MusicBrainz 上也查不到，
直接在定时任务里订阅会持续攒出一堆**必然失败**的订阅记录。先缓存、再校验、
后推送，既不丢歌，也不脏订阅列表。

**订阅粒度**（推送待处理曲目、以及选「立即自动转为音乐订阅」时生效）：

| 选项 | 行为 |
| --- | --- |
| 仅单曲 | 只按「歌手 + 歌名」订阅单曲 |
| 单曲优先，失败转所在专辑 | 先试单曲；识别不到时改订阅歌曲**所在专辑** |
| 仅订阅所在专辑（插件默认） | 只订阅专辑，一张专辑到齐即整单完成 |

**为什么按专辑订阅成功率更高？** 宿主对音乐订阅要求识别结果带媒体身份
（media_source / media_id），默认只按 MusicBrainz 搜标题——中文歌在 MusicBrainz
覆盖率低（且其服务经常 503），这就是日志里大量
`音乐订阅未新增：XXX（未识别到媒体信息）` 的原因。本插件的识别梯：

1. **豆瓣音乐源**（宿主内置 `doubanmusic`，中文覆盖率远高于 MusicBrainz，
   且返回结果自带身份与专辑曲目总数）——单曲或专辑优先识别；
2. **MusicBrainz**（宿主默认路径）兜底；
3. 拿到专辑订阅需要的 `total_tracks`（曲目总数）后才会发起专辑订阅，
   否则自动放弃该途径，避免产生必然失败的订阅。

同步时会把曲目的**专辑名**一路带入订阅流程（网易云 / 汽水的曲目数据都带专辑字段），
这是「订阅歌曲所在专辑」能精准命中的关键。

### 2.4 库内缺失曲目：缓存 → 网易云校验 → 手动推送

配置页「库内缺失曲目：网易云校验 + 手动推送订阅」面板（序号留空表示全部）：

| 按钮 | 作用 |
| --- | --- |
| 校验（去网易云） | 拿清单里的曲目去 `music.163.com` 搜索，确认真实存在，并回填 `song_id`、权威歌名 / 歌手 / 专辑 |
| 推送订阅 | 把选中条目按上面选的粒度推送到 MoviePilot 音乐订阅，专辑名一并带入识别梯 |
| 移除选中 | 从清单里删掉选中条目 |
| 清理已推送 | 清掉已经推送成功的条目，保持清单干净 |

**校验怎么判断命中**：歌名 / 歌手先做归一化（去掉 `(Live)`、`【现场版】` 这类
括号补充说明与标点空白，不区分大小写），再按标题权重高于歌手逐条打分取最高分；
分数过低判定为「网易云未找到」，接口异常记为「校验失败」，两种情况都只记状态、
不影响其它条目。校验拿到的专辑名会在推送时优先作为订阅线索，命中率比只给歌名高。

**序号在哪里看**：插件详情页的「待处理清单」表格，序号只增不减，便于长期引用。

### 2.5 QQ音乐 / 网易云歌单同步设置

一行一个歌单，格式（三处栏位互相独立）：

```
歌单id:播放列表名称[:emby用户名]
```

- QQ音乐：`2362260213:经典歌曲`
- 网易云：`2362260213:经典歌曲`（歌单 id 取自 `https://music.163.com/#/playlist?id=歌单id`）
- Emby 多用户：`2362260213:经典歌曲:doumao,tudou`

### 2.6 汽水音乐歌单同步设置

```
汽水音乐分享链接:播放列表名称[:emby用户名]
```

**分享链接怎么获取：**

| 步骤 | 操作 |
| --- | --- |
| 1 | 打开汽水音乐 App → 底部「我的」 |
| 2 | 点开要同步的歌单（必须是自己创建或已收藏的公开歌单） |
| 3 | 点右上角 `⋮`（更多）→「分享」 |
| 4 | 「复制链接」，得到形如 `https://qishui.douyin.com/xxxxxxx` 的链接 |
| 5 | 粘贴到插件配置里，冒号后可自定义播放列表名 |

注意：歌单必须是**公开可访问**的（私密歌单解析不到）；解析走第三方公共接口，
限 30 次/分钟，配置多行时插件会逐条解析、单条失败不影响其它行。

## 3. 插件详情页

配置页顶部点「详情」进入，样式对齐自动订阅助手的概览页：

- **统计卡片**：同步歌单数 / 同步曲目 / 本次新增 / 库内缺失 / 音乐订阅 / 异常条目；
- **同步明细卡片网格**：每个歌单一张卡，含来源、媒体服务器、数量与失败原因；
- **订阅情况**：本次新增、已存在/未识别、失败数量与订阅明细表；
- **待处理清单**：库里缺失的歌曲明细（序号、歌曲、歌手、专辑、来源、命中次数、
  校验结果、网易云匹配、推送状态），以及待处理 / 待推送 / 已确认 / 已推送的统计标签。
  清单里的**序号**就是配置页校验与推送时要填的值。

> 详情页是**只读**的（宿主 JSON 模式在详情页不支持按钮事件），所有管理动作
> 都放在配置页执行，避免"按钮点了没反应"的假交互。

## 4. 音乐订阅管理（配置页底部，保存即执行）

| 动作 | 说明 |
| --- | --- |
| 删除本插件创建的全部音乐订阅 | 清空本插件登记的所有订阅 |
| 删除身份不完整的音乐订阅 | 清理识别残留的脏数据（无 media_source/media_id 的音乐订阅） |
| 按订阅 ID 删除 | 填 ID（逗号分隔），ID 可在详情页订阅明细里查 |

也可直接调接口：

```bash
# 查看本插件登记的订阅
GET  /api/v1/plugin/MusicSubscribe/subscribes
# 按 ID 删除
POST /api/v1/plugin/MusicSubscribe/subscribes/remove?ids=12,15
# 批量清理：scope=own（本插件创建）/ scope=unrecognized（身份不完整）
POST /api/v1/plugin/MusicSubscribe/subscribes/clear?scope=own
# 最近一次同步统计 / 每日推荐接口诊断
GET  /api/v1/plugin/MusicSubscribe/stats
GET  /api/v1/plugin/MusicSubscribe/diagnose

# 待处理清单：查看 / 校验 / 推送 / 移除 / 清理
GET  /api/v1/plugin/MusicSubscribe/pending
POST /api/v1/plugin/MusicSubscribe/pending/verify?ids=1,3
POST /api/v1/plugin/MusicSubscribe/pending/push?ids=1,3
POST /api/v1/plugin/MusicSubscribe/pending/remove?ids=1,3
POST /api/v1/plugin/MusicSubscribe/pending/clear?scope=pushed
```

`ids` 留空表示全部；`scope` 支持 `all`（清空）与 `pushed`（只清已推送成功的条目）。

## 5. 使用前提

- MoviePilot **v3.0.0 及以上**（音乐订阅链、统一媒体身份）；
- Plex：音乐库类型为 `artist`/`music`；Emby：音乐库可用且能取到用户；
- 网易云相关功能（歌单 / 每日推荐 / 听歌模式 / 缺歌校验）需要先在插件里登录网易云；
- 同步只添加媒体库**已有**歌曲，不会自动下载音乐；待处理清单的「推送订阅」只是
  在 MoviePilot 里建订阅，下载仍由 MoviePilot 自己的订阅链负责。

## 6. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 每日推荐/听歌模式失败，提示需要登录 | 到配置页重新登录网易云；可用「诊断每日推荐接口」按钮看返回码与条数 |
| 提示触发网易风控（code=460） | 降低同步频率，稍后再试；不要把 ncm-api 暴露在公网被多人共用 |
| 详情页待处理清单一直涨但没订阅 | 默认处理方式就是「缓存待处理」，需要在配置页填序号后点「校验」再「推送订阅」；想全自动就改成「立即自动转为音乐订阅」 |
| 校验结果全是「网易云未找到」 | 歌名可能带了大段括号副标题或日文/罗马音差异，可先「移除选中」再手工在配置页填歌单实际歌名；也可确认登录态是否过期 |
| 校验结果「校验失败」 | ncm-api 不可达或接口异常（插件已自动在 `/cloudsearch` 与 `/search` 间回退），检查 ncm-api 容器与端口（默认 1630） |
| 推送后状态还是「待推送」 | 该曲目在识别梯里仍未命中（返回「已存在或未识别」），可稍后重试或改用「仅订阅所在专辑」粒度 |
| 音乐订阅大量「未识别到媒体信息」 | 属正常现象的兜底日志；粒度选「单曲优先，失败转所在专辑」或「仅订阅所在专辑」，豆瓣音乐源识别会覆盖大部分中文歌；MusicBrainz 503 时稍后重试 |
| 专辑订阅没生效 | 该专辑在豆瓣/MusicBrainz 查不到曲目总数，宿主无法累计专辑进度，插件会自动放弃该途径 |
| 汽水歌单解析失败 | 确认是**公开**歌单、链接完整；限流（30 次/分）时稍等再同步 |
| Plex 播放列表没建出来 | 确认 Plex 有 `artist`/`music` 类型媒体库；插件只搜得到库里已有的歌 |
| 同步了但歌曲很少 | 精准匹配要求歌手一致；关掉「精准匹配」可放宽（同名歌可能串） |
| 配置某一行格式错了 | 只会跳过该行并记录到详情页，不影响其它歌单与每日推荐 |
