# 歌单订阅（MoviePilot V3）

把网易云 / QQ音乐 / 酷狗 / 酷我 / 咪咕 / Spotify 等平台的歌单同步成 Plex / Emby 的播放列表，并把媒体库里搜不到的曲目汇总成一份**待订阅清单**，由你在数据页勾选后一键推送订阅，成功的留进**订阅历史**（带歌曲 / 专辑 / 歌手的**来源链接**，即该曲目在最初所属平台上的详情页）。

**核心能力：**

1. **同步 / 创建歌单** —— 网易云、QQ音乐、酷狗、酷我、咪咕、Spotify 的歌单，以及网易云每日推荐（歌单 / 歌曲），同步成 Plex / Emby 的音乐播放列表，曲库里已有的曲目不重复添加；
2. **库内缺失歌曲订阅** —— 同步时媒体库里搜不到的曲目，按「歌名 + 歌手」跨歌单去重后落到清单里（含歌曲名、时长、歌手、专辑名称、来源歌单、命中次数），在数据页逐行勾选「歌曲」或「专辑」，点「订阅」推送给 MoviePilot 的音乐订阅；
3. **播放列表总览回写** —— 每同步完一个播放列表，把「来源平台 · 歌单名、同步时间、曲目统计」写进媒体服务器里播放列表的总览（摘要），在 Plex / Emby 里点开播放列表就能看到这份歌单从哪来、什么时候同步的（详见第 8 节）；
4. **批量订阅 + 分批执行** —— 数据页可一键「选择当前页」，按每批 10 / 20 / 50 / 100 条顺序推送，批间刷新清单与总览、实时显示「第 x / y 批」进度，订阅中可随时「停止」且剩余勾选保留续订。

插件**不会**在同步过程中自动订阅任何东西，每首歌怎么订阅都由你决定。

## 1. 部署 ncm-api（网易云取数的前置条件）

网易云的登录与取数全部交给本地部署的 [ncm-api](https://github.com/moefurina/ncm-api) 容器，插件不内置加密实现。  
ncm-api 容器端口 3000 与 MoviePilot 冲突，宿主机映射端口统一用 **1630**。

**与 MoviePilot 同一个 docker-compose（推荐）**

```yaml
services:
  moviepilot:
    image: jxxghp/moviepilot:latest
    # ……省略自身配置……
  ncm-api:
    image: moefurina/ncm-api:latest
    container_name: ncm-api
    restart: always
    ports:
      - "1630:3000"
```

服务地址填 `http://192.168.X.X:1630`（同一 compose 网络内可写 `http://ncm-api:3000`）。

**ncm-api 跑在宿主机**

```bash
docker run -d --name ncm-api -p 1630:3000 moefurina/ncm-api:latest
```

服务地址填 `http://127.0.0.1:1630`（MoviePilot 也跑在宿主机时）或宿主机内网 IP。

**在局域网另一台机器**：服务地址填 `http://那台机器的内网IP:1630`，注意那台机器要能访问网易云。

## 2. 配置页

| 分区    | 说明                                                                                                              |
| ----- | --------------------------------------------------------------------------------------------------------------- |
| 运行设置  | 启用开关、定时同步周期（cron）、同步到哪些媒体服务器、曲目精确匹配、订阅人、订阅并发数（1~8）、订阅即入队、曲库索引                                                                         |
| 网易云   | ncm-api 服务地址 + 连通性探测、扫码登录、当前登录状态与「退出登录」按钮                                                                       |
| 歌单来源  | 网易云歌单 / 每日推荐、QQ音乐歌单、其它平台歌单（酷狗 / 酷我 / 咪咕 / Spotify，`平台|标识符|名称` 格式）、Spotify 凭据（client_id / client_secret，填了才把 Spotify 计入可用平台）、各平台可用性一览                                 |
| 上次同步  | 上次同步耗时、新增曲目、库内缺失数量、运行状态（同步进行中 / 上次跳过时间）、分段耗时（抓歌单 / 推送 / 登记缺歌）、索引曲目数，以及每个播放列表的结果明细                                                                                |

### 2.1 网易云登录

只保留**扫码登录**一种方式。退出登录是一次性按钮动作，插件不再有「Cookie 保活」这类后台开关：

点「获取二维码」→ 用网易云音乐 App 扫码 → 页面自动轮询到授权成功。登录凭证与歌单取数全部由 ncm-api 持有，插件不保存密码，也不再提供短信验证码、账号密码、手动粘贴 Cookie 的入口。

### 2.2 订阅人

订阅时写进宿主订阅记录的「用户」栏位，默认 **`歌单订阅`**。想按人区分订阅来源（或跟手工订阅区分开）就改这里。

搜索来源**不在插件里选**：插件不指定任何音乐来源，搜哪些库完全由宿主自己的音乐元数据源设置决定。要调整命中率，请去「设置 → 音乐元数据源」改宿主的来源配置。

### 2.3 歌单配置格式

每行一条，空行与 `#` 开头的注释行会被忽略：

```
# 网易云 / QQ音乐：歌单ID:播放列表名称[:emby用户名]
2388086885:我喜欢的音乐
https://music.163.com/playlist?id=2388086885:午后咖啡
2388086885:收藏:张三,李四

# 其它平台（酷狗 / 酷我 / 咪咕 / Spotify）：平台|标识符|播放列表名称[:emby用户名]
spotify|https://open.spotify.com/playlist/xxx:每日推荐
kugou|12345:华语精选
```

- `播放列表名称` 是同步后在 Plex / Emby 里显示的歌单名，必填；
- `emby用户名` 只对 Emby 有效（多人各用各的播放列表），多个用户用半角逗号分隔；
- 网易云 / QQ音乐的歌单可以直接粘贴歌单链接，插件会自己从中取出数字 ID；
- 酷狗 / 酷我 / 咪咕 / Spotify 写在「其它平台歌单」栏位，用 `|` 分隔（标识符可能是 URL，
  冒号会和 `https://` 冲突）。

### 2.4 曲目精确匹配

- **开启**（默认）：歌名命中（相等或互相包含）后，**「歌名 + 专辑名」或「歌名 + 歌手」任一命中即算匹配**——专辑命中优先，同一首歌的多个版本取码率最高的。相比只认歌手，专辑名也能把「媒体库里有、歌手名写法不同」的曲子救回来，减少「明明有却判成缺失」；
- **关闭**：只按歌名模糊匹配，匹配更宽松，但可能并入同名不同版本的曲目。

### 2.5 外部接口限速

公开接口都有频率限制，插件在请求侧自己排队，宁可多等几秒也不要整轮失败：

| 数据源               | 限速            | 说明                              |
| ----------------- | ------------- | ------------------------------- |
| QQ音乐              | **1 次 / 5 秒** | 模块级共享节流，跨歌单生效；等待时日志会写明「已等待 N 秒」 |
| 网易云（自部署 ncm-api）  | 不限            | 本地服务，自己控制即可                     |

所以配了 N 个 QQ音乐歌单时，一轮同步至少多花 `(N - 1) × 5` 秒，属正常现象。

### 2.6 性能与资源占用（v2.4.0 起）

针对「歌单多、媒体库大、一轮同步跑得久」的场景做了一轮系统性改造，十项机制叠加，默认全开：

| 机制 | 配置项 | 默认 | 作用 |
| --- | --- | --- | --- |
| 曲库索引 | `library_index` | 开 | 同步前按服务器把整个音乐库建成带 TTL（10 分钟）的本地索引（上限 2 万条，超限按缺歌裁剪），曲目匹配全部走本地索引，**单轮媒体库检索请求从「每首一次」降为「每服务器一次」** |
| 有界并行订阅 | `subscribe_workers` | 2（1~8） | 缺歌订阅改走线程池并发识别 + 订阅，失败重试与结果汇总只在主线程完成，清单一次落盘 |
| 订阅即入队 | `immediate_search` | 开 | 勾选订阅成功后顺手把订阅 ID 推入宿主搜索队列，并由守护线程恢复队列，不用等宿主下一轮计划任务 |
| 歌单快照 | （内置） | 开 | 每个歌单的曲目按歌单位号落盘，同轮多次同步直接复用；抓取失败沿用上次快照并在明细里打 `stale` 标记 |
| 同步互斥 | （内置） | 开 | 新一轮启动时以非阻塞方式抢类级锁，抢不到就跳过本轮并记录 `skipped_at`，定时任务与手动触发不会叠跑 |
| 预查去重 | （内置） | 开 | 订阅前先查宿主已有订阅与订阅历史，命中的直接出清单，不再制造「已存在」式无效订阅 |
| 失败退避 | （内置） | 开 | 订阅失败的条目记录 1 小时冷却（`retry_at`），倒计时归零前勾选会被跳过并提示「约 N 分钟后自动重试」 |
| 历史治理 | （内置） | 开 | 订阅历史按 90 天自动清理，仍被宿主订阅中的记录保留 |

配套的可观测信息：数据页顶部显示**运行状态**（同步进行中 / 上次跳过时间）与**分段耗时**（抓歌单 / 推送 / 登记缺歌），同步记账里还记录索引曲目数、是否命中索引、复用快照次数。

## 3. 数据页（库内缺失曲目）

列表与你看到的截图完全一致：

| 序号 | 选择歌曲 | 选择专辑 | 歌曲名称 | 时长    | 歌手 | 专辑名称  |
| -- | ---- | ---- | ---- | ----- | -- | ----- |
| 1  | ○    | ●    | 我记得  | 05:29 | 赵雷 | 署前街少年 |
| 2  | ●    | ○    | 红豆   | 04:16 | 王菲 | 畅游    |

- **同一序号的「歌曲」与「专辑」二选一**：同一个 `seq` 只能是一种粒度，点另一个会自动切过来；
- **全选 / 反选 / 选择当前页**：「全选」把当前筛选出来的记录全部选中为「歌曲」；「选择当前页」只勾选当前分页显示的行（歌单多的时候不用翻页全选再取消）；「反选」未勾选 → 勾选歌曲；已选歌曲 → 切成专辑（没有专辑信息则取消）；已选专辑 → 取消；
- **分批订阅**：底部可选「每批」10 / 20 / 50 / 100 条，点「订阅」后按批顺序推送，批间自动刷新清单与总览，进度显示「第 x / y 批（本批 N 条）」；订阅中可以点「**停止**」中断，**剩余勾选保留**，改天可以再点「订阅」继续；
- **订阅**：按勾选的粒度逐条推送给 MoviePilot 音乐订阅；**成功的记录从清单移出并留一份订阅历史**，只有失败的会留在清单里，行内标红并写明失败原因；失败超过 1 小时冷却期的行会显示「约 N 分钟后自动重试」倒计时；
- **来源链接**：每行直接给出这首歌在**来源平台**（网易云 / QQ音乐 / 酷狗 / 酷我 / 咪咕 / Spotify）上的**歌曲 / 专辑 / 歌手**详情页链接，随同步算好、无需再点「查询链接」，点开即回到那家平台上的具体歌曲（查不到对应 ID 的维度置灰）；
- **移除 / 清理**：移除勾选的记录，或清理「订阅失败」的记录 /「全部」；
- 顶部统计卡显示**总数**、**订阅失败数**与**订阅历史**条数，另有关键词搜索、数据源过滤与分页（每页 20 / 50 / 100 条）；
- **运行状态**：同步进行中时顶部显示「歌单同步：进行中」，数据页按约 5 秒自动刷新——总览、清单与「上次同步缺失」在长轮同步中持续保鲜；因互斥跳过上一轮时显示上次跳过时间，并附分段耗时（抓歌单 / 推送 / 登记缺歌）一行。

### 3.1 订阅历史

顶部「待订阅清单 / 订阅历史」两个视图随时切换。订阅成功的条目会留档在这里：

| 序号 | 歌曲名称 | 歌手     | 专辑名称 | 时长    | 粒度 | 订阅人  | 订阅时间                | 来源链接         |
| -- | ---- | ------ | ---- | ----- | -- | ---- | ------------------- | ------------ |
| 1  | 起风了  | 买辣椒也用券 | 起风了  | 05:26 | 歌曲 | 歌单订阅 | 2026-09-23 15:04:11 | 歌曲 / 专辑 / 歌手 |

- 历史里直接给出歌曲、专辑、歌手三个来源链接（指向最初所属平台，取不到的置灰）；
- 订阅 ID 一并记录，方便回宿主的订阅列表里对照；
- 支持按关键词搜索、按订阅粒度（歌曲 / 专辑）过滤，可单独清空；**清空历史只动插件自己的留档，不会删除宿主里的订阅**。

清单上限 1000 条，超出后丢弃最早的记录。

**执行顺序**：一次同步里先把所有歌单推完（该加的歌照常加进播放列表），每个歌单里搜不到的歌只做登记并按「歌名 + 歌手」跨歌单去重（命中次数累加、来源保留第一次见到的歌单），全部推完后统一写入清单。中途出错也不丢已发现的缺歌。

## 4. 订阅是怎么落的

全链路走宿主的**官方音乐接口**，插件自己不实现任何来源协议：

1. **搜索** —— 拿「歌手 + 歌名」调宿主的音乐搜索（`GET /api/v1/music/search`），按实体类型过滤出单曲 / 专辑候选。**不指定来源**，由宿主按自己的音乐元数据源设置决定搜哪些库；
2. **识别** —— 对命中的候选按「来源 + 媒体 ID」调官方识别（`POST /api/v1/music/recognize`）拿到完整详情。走的是**音乐专用入口**（不经过会把请求广播给影视插件的通用识别链）；歌名对不上或歌手明显不符的候选直接放弃，专辑拿不到曲目总数的按失败处理；
3. **订阅** —— 识别结果带 `media_source` / `media_id` 交给 `SubscribeChain` 显式订阅，并带上配置里的**订阅人**与**来源标签**（形如 `订阅人:服务器/歌单`，宿主签名不兼容时按「带用户名 + 来源 → 只带用户名 → 裸调」三级降级），订阅历史与清单因此可回溯到具体服务器与歌单。

选「歌曲」按单曲（`recording`）订阅，选「专辑」按所在专辑（`album`）订阅。只采信**音乐来源**的识别结果：宿主识别是插件优先的模块广播，影视类插件若不校验 `media_source` 就按标题返回结果会抢先命中，这类结果一律按未识别处理。

推送订阅前还会先查一次宿主的已有订阅与订阅历史，命中的曲目直接出清单、不再重复订阅。

搜不到、识别不出身份、或候选对不上的曲目，会留在清单里并写明原因（例如「未搜索到匹配的曲目」「识别结果不是音乐来源」），等你自己决定要不要换个关键词或换来源再试。

## 5. 定时任务

在「运行设置」填五位 cron 表达式即可，例如每天凌晨 4 点：`0 4 * * *`。  
留空表示不定时运行，只能手动点配置页底部的「立即运行一次」。保存配置不会触发同步——保存入口在宿主头部右上角，与运行动作互不打扰。

## 6. 接口

完整路径为 `/api/v1/plugin/MusicSubscribe/<path>`：

| 方法   | 路径                   | 说明                                                                                                          |
| ---- | -------------------- | ----------------------------------------------------------------------------------------------------------- |
| GET  | `/status`            | 版本、开关、登录态、媒体服务器、清单概览、上次同步统计（含 `running` 同步进行中标志与 `metrics` 分段耗时）                                                                                 |
| GET  | `/probe`             | 探测 ncm-api 连通性                                                                                              |
| POST | `/qrcode`            | 获取扫码登录二维码                                                                                                   |
| GET  | `/qrcode/status`     | 查询扫码状态（成功后自动保存登录）                                                                                           |
| POST | `/logout`            | 退出网易云登录并清除本地凭证                                                                                              |
| POST | `/run`               | 立即运行一次同步（互斥抢锁失败会跳过本轮并记录 `skipped_at`）                                                                     |
| GET  | `/pending`           | 查询库内缺失曲目清单（`scope=all/failed`，`failed` 为订阅失败的记录；每条含 `retry_in` 冷却倒计时，响应带 `running` 与 `stats.metrics`）                                                            |
| POST | `/pending/subscribe` | 按勾选的粒度推送订阅（body：`{"items":[{"seq":1,"target":"song"}]}`），成功的记录从清单移出并写入订阅历史；并发执行（`subscribe_workers` 路），返回 `search_queued` 送入宿主搜索队列的数量                                  |
| POST | `/pending/remove`    | 从清单移除勾选的记录                                                                                                  |
| POST | `/pending/clear`     | 清理清单（`scope=all/failed`）                                                                                    |
| POST | `/pending/link`      | 查询单条曲目的来源链接（body：`{"seq":1}`，返回歌曲 / 专辑 / 歌手三个链接，指向该曲最初所属平台）                                       |
| GET  | `/history`           | 查询订阅历史（只含订阅成功的条目，支持 `keyword` 搜索）                                                                           |
| POST | `/history/clear`     | 清空订阅历史（不影响宿主订阅列表）                                                                                           |
| GET  | `/platforms`         | 列出全部平台及其歌单获取可用性（含停服 / 未配置说明），供配置页展示                                                                             |

> v2.5.0 起删除了 `/search`、`/download`、`/bitmagnet/test`、`/smartlist` 四个接口（跨平台搜索、下载、bitmagnet 种子回退、智能歌单整体下线），平台适配器只保留歌单获取。

## 8. 播放列表总览（v2.5.0 起）

每同步完一个播放列表，插件会把本轮结果写进媒体服务器里这个播放列表的**总览**（Plex 播放列表编辑弹窗里的「总览」一栏 / Emby 的「概览」）：

```
由「歌单订阅」同步自 网易云 · 我喜欢的音乐
同步时间 2026-10-24 04:00:12｜歌单 30 首｜本次新增 28 首｜库内缺失 2 首（见插件数据页）
```

- 之后在 Plex / Emby 里点开这个播放列表，就能看到它从哪来、什么时候同步的、这轮加了多少、还缺多少，不用回插件里翻；
- 总览是**附加信息**：写失败只记日志，不影响歌单推送与清单本身的结果；
- Plex 走 plexapi 的播放列表编辑入口（`PUT /playlists/{id}?summary=...`），老版本 plexapi 没有该方法时自动改直连接口兜底；
- 同步统计本身也改为**按歌单增量落盘**，数据页在同步进行中按约 5 秒轮询——一轮同步要跨多个歌单与服务器，中途总览与清单持续保鲜，被打断也不丢已完成部分的进度。
